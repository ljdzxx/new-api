# 上游请求超时与取消

- `RELAY_TIMEOUT`：非流式上游请求的总超时，单位秒，默认 `0`（不限制）。
- `STREAMING_TIMEOUT`：流式请求等待响应头、以及读取流期间的无数据超时，单位秒，默认 `300`。小于等于 `0` 时回退为 `30` 秒；不限制流式请求的总时长。
- 通用 HTTP 流式读取收到一行后重新计时，AWS Bedrock SDK 收到一个事件后重新计时。向客户端发送的保活消息不会延长上游等待时间。

通用 HTTP 转发同时保留出站请求原有的 context，并监听客户端断开。取消会传播至等待响应头和读取响应体阶段；响应体关闭时先取消请求，再关闭响应体。HTTP/2 取消当前请求流，不主动关闭其他请求共享的连接。

AWS Bedrock 的同步调用继承客户端 context，并应用 `RELAY_TIMEOUT`；流式调用分别限制等待响应头和事件空闲时间。超时或客户端断开时取消 SDK 调用并关闭事件流，保留已收到的用量和部分输出估算用于原有结算流程，不补发成功终止事件。

客户端断开不会触发渠道重试、渠道故障记录或向断开的客户端补写错误。明确使用独立后台 context 的任务继续遵循其自身生命周期。

取消 HTTP 请求能终止本系统的等待并向上游传递断开信号。上游及中间代理是否停止推理，仍取决于它们是否实现取消传播；此机制不调用供应商特定的异步任务取消接口。
