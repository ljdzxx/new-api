# 注册风控

控制台入口：系统设置 → 运营设置 → 邀请奖励风控 → 注册风控。

注册风控默认关闭，与邀请奖励风控的评分开关独立。仅启用 Redis 时生效，作用于普通注册和标准 OAuth 首次建号（含自定义 OAuth）。已有用户登录、账号绑定、管理员建号不参与注册次数判断。微信注册不采集或保存画像，也不参与注册风控。

## 规则

- 复用邀请奖励风控的十项画像指标：精确 IP、整体浏览器指纹、Canvas、WebGL、音频、字体、UA、语言与时区、屏幕、硬件。固定顺序拼接服务端 HMAC 后生成画像 KEY；不使用评分权重。
- 首次记录的 value 为 0，后续每次完整画像匹配加 1。当 value 大于等于命中阈值时拒绝注册。默认阈值 1，即同一画像第二次注册被拒绝。
- 默认冷却时间为 24 小时，可设置 1～720 小时。每次命中（包括被拒绝的请求）都会刷新冷却时间；连续没有命中满一个冷却周期后，记录才会过期。
- 任意指标变化，包括 IP 变化，都会产生新的画像。客户端指纹属于辅助信号，应继续使用验证码和请求限流。
- 无效、过期、重复使用的采集令牌，缺失或不一致的核心指纹均拒绝本次注册。浏览器不支持的可选能力以空值参与拼接，不能把所有可选设备能力都省略。Redis 发生故障时不降级放行。
- 失败提示词适用于达到命中阈值；采集异常和服务故障返回对应语言的重试提示。

## 存储与部署

`RegisterRiskControlEnabled`、`RegisterRiskCooldownHours`、`RegisterRiskHitThreshold`、`RegisterRiskRejectMessage` 保存在现有 options 表中，无新增数据库迁移。设置只影响后续请求；修改冷却时间不会主动改写已有 KEY，但再次命中会采用新冷却时间。

计数 KEY 格式为 `register_risk:v1:{画像摘要}`，value 是整数。关联的 `:epoch` 用于区分冷却周期，`:receipt:请求ID` 用于并发预占和失败补偿。所有 KEY 均有过期时间。数据库建号之前原子预占；建号确定失败时仅补偿本次预占，不回退其他请求的命中或刷新时间。若进程在建号期间退出，或数据库提交结果无法确认，保守保留该次计数直至冷却过期，避免已建号却返还次数。

Redis 启用时，采集 challenge（5分钟）和一次性 token（15分钟）也存放在 Redis，支持跨实例请求。关闭 Redis 时，保留现有邀请奖励采集使用的进程内存存储，注册限制不生效。

部署时必须为所有实例配置相同且稳定的 `CRYPTO_SECRET`（或其回退值 `SESSION_SECRET`），并使用同一个 Redis 数据库。密钥变化会改变画像摘要，使历史记录无法匹配；不配置稳定密钥时，进程重启也会造成这一问题。Redis 数据应避免被缓存淘汰策略提前驱逐；清空或丢失计数数据会重置冷却记录。

## 验证

`go test ./common ./model ./controller` 覆盖参数边界、精确画像、并发注册、滑动冷却、失败补偿、过期周期隔离、Redis 故障、跨连接令牌校验、防重放、微信画像排除及注册入口行为。

前端使用 `bun run build` 验证生产构建。
