# 渠道模型可用性监控

在“系统设置 → 运营设置 → 监控设置”开启模型可用性监控。默认关闭，默认状态码为 `429,502,503`，连续相同状态码阈值为 `2`（允许 1–1000）。

- 按渠道 ID 和渠道配置中的模型名称统计；上游模型映射不合并不同的对外模型别名。
- 每次渠道尝试只记录最终结果。Responses reasoning 有损恢复后成功按成功处理，恢复仍失败只计一次。明确的 `invalid_encrypted_content`、本地异常和客户端取消不累计。
- 使用真实上游 HTTP 状态码；渠道状态码映射不影响统计。HTTP 200 内的流式错误不转换为 502。其他有效 HTTP 结果打断当前连续计数。
- 连续两次 429 或连续两次 502 可以触发；429 后跟 502 只算连续一次 502。并发结果按缓存原子提交顺序计算。
- 不可用模型从首次选渠、重试、亲和性中排除；指定渠道和转发目标也要通过检查。已经发出的请求不强制中断。
- 管理员测试该模型通过后恢复该模型并清零计数。后台自动测试不恢复模型状态；其他模型不受影响。恢复前发出的旧请求不能覆盖恢复结果。
- 视频、异步任务及不支持模型测试的专用渠道不参与本监控。Realtime 不参与基于 HTTP 请求结果的本次监控。

## 控制台

渠道列表状态列展示模型可用性汇总，点击进入模型测试窗口查看每个模型的状态、失败码/次数、停用时间和测试恢复时间。无历史记录显示“暂无观测”，默认允许选路。页面只在打开、手动刷新或测试完成后获取状态，没有轮询或推送。

关闭功能后停止统计和拦截，保留缓存记录；再次开启继续使用。修改状态码集合或阈值会重置尚未停用模型的连续计数，已停用的模型仍需管理员测试恢复。整渠道自动禁用和余额不足规则独立生效，模型测试恢复不保证整渠道已满足其他路由条件。

## 缓存与多实例

运行状态不写数据库，不设自动过期时间。未配置 Redis 时使用进程内存；配置 Redis 时使用共享 Redis，原子更新并对重复提交去重，不在 Redis 故障时静默切回空内存。

- 内存模式重启会清空状态，不适用于需要统一状态的多实例部署。
- 多实例使用同一 Redis。状态变化无需等待渠道配置缓存同步。功能启用仍遵循项目现有的设置同步周期；Redis 中共享的监控规则防止尚未同步的节点使用旧阈值重置计数。
- 应用重启不清空 Redis 状态；Redis 重启后的保留程度取决于部署的持久化、复制和淘汰策略。缓存记录丢失会回到默认可路由，不能保证只经人工测试恢复。
- Redis 查询失败时返回状态检查错误。请求已经执行后若结果写入失败，仅记录后台错误，不重发请求，也不改变已返回的成功结果。管理员测试通过但恢复写入失败时，界面明确报告恢复失败。
- 删除渠道或移除配置模型会清理对应状态；正常请求结束时不会重新创建已经清理的状态。

配置仍使用现有系统设置存储；新增状态没有数据库表和迁移。Redis 状态命名空间为 `new-api:model_health:v1`，共享规则为 `new-api:model_health:config:v1`。
