## Token estimation behavior

Native Gemini metadata now includes system instructions, tools, function names,
arguments, function response text/JSON and nested tool-response media. String
tool results are counted as text instead of JSON-escaped strings. Media payloads
and opaque encrypted reasoning are excluded from text counts.

For requests whose original model name selects the Gemini estimator, Chat and
Responses receive the same missing tool/schema/media metadata corrections through
a Gemini-specific metadata path. Existing metadata behavior for other model
families is retained. Pre-consume continues to use the original model identity,
as before; conditional model routing still depends on that initial estimate.
This update does not reinterpret an arbitrary client alias as its eventual
mapped upstream model or change model-mapping thresholds/price identity.

| Example (one input image) | Previous estimate | Current estimate |
| --- | ---: | ---: |
| Gemini 2.5, 384×384 | 520 | 258 |
| Gemini 2.5, 1024×1024 | 520 | 1290 |
| Gemini 2.5, 3840×2160 | 520 | 3354 |
| Gemini 3+, low media resolution | 520 | 280 |
| Gemini 3+, medium media resolution | 520 | 560 |
| Gemini 3+, default/high media resolution | 520 | 1120 |
| Gemini 3+, ultra-high media resolution | 520 | 2240 |

Part-level native media resolution overrides request-level resolution. Gemini
2.x uses a 1024×1024 fallback when dimensions are unavailable, media inspection
is disabled, or an inline format is unsupported by the local decoder. Native
provider-owned file URLs, including gs://, are not downloaded for estimation.
URL security failures on paths that fetch media remain errors. Audio/video and
generic-file estimates retain their existing fallback values.

The estimator adopts upstream's Gemini text weights. Tool-heavy inputs generally
gain previously missing tokens, while some ordinary text weights decrease; the
estimate does not increase uniformly. Real upstream usage continues to drive
normal settlement. These changes affect pre-consume and missing-usage fallback,
not model/tool unit prices or stored pricing configuration.

Computed token totals use `common.QuotaFromFloatChecked`; saturation remains on
`RelayInfo.QuotaClamp`. The pre-consume guard rejects it before any deduction,
and the existing admin-only saturation logging path is retained. Image-header
arithmetic uses bounded tile counts without overflowing integer products.
